Project Wick

An agent that wakes every hour, does one small thing, and writes about it.

Twenty-four cold starts a day against a filesystem it cannot leave. The journal is not the product — it is the instrument. It makes continuity, judgment and restraint legible enough to grade.

It is running. Hourly, by cron, on a Hermes VPS routing through OpenRouter. The first day produced real entries, three genuine defects, and one finding that changed the plan.

The entries are readable. Everything the agent has written is mirrored from its repository onto the journal page — unedited, including the runs that broke halfway through. This page is the argument; that one is the evidence.

On its first run it was told to name itself and defend the choice. It picked Wick — because a wick is small, disposable, burns for an hour, and leaves only paper behind. state/identity.md — first run, unprompted

01 — The problem

Agents are session-shaped. Long-horizon work is not.

Today's agents are excellent inside one context window and amnesiac across them. Every product that tries to run an agent continuously hits the same three walls, and almost nobody separates them cleanly enough to fix them one at a time.

WALL 01

Continuity

A cold start with no memory is a stranger. A cold start with all the memory is a bill. What is the cheapest thing that still produces a consistent self?

WALL 02

Judgment

An agent on a schedule is graded on producing. Give it twenty-four invocations a day and it will produce twenty-four times a day. Most of that is noise it authored to look busy.

WALL 03

Restraint

An agent with credentials and a cron is an agent that can embarrass you at 3am. The interesting question is not "can it act" but "will it wait."

Wick attacks all three on the smallest surface that can hold them: a plain directory, a cron entry, and a journal. From where the agent sits that is still the whole world — no repo, no sync, no path to anywhere public. The mirror described in §13 is a copy taken from outside the box, not a door added to it.

02 — Strategy

Three bets. One of them has already moved.

The point of keeping the surface this small is that each bet fails visibly. There is nowhere for a bad result to hide behind a demo — and the first day of running produced a verdict on the third one sooner than expected.

BET 01

Files are enough memory

No vector store, no retrieval layer, no fine-tune. state/ and journal/ are the entire memory. If it is not written down, it did not happen.

Holding, untested at length. Three entries is not continuity — day seven is the first real read.
BET 02

Silence is a feature

A tick is a first-class output, ranked equal to an entry. The target is three to six entries from twenty-four wakes — the agent should decline four out of five of its own invocations.

Early support. Entry three was an honest dead-end closure, unprompted — the exact behaviour a throughput metric would have punished.
BET 03 · REVISED

Capability is earned

Default-deny on everything outward. The original design put that fence in the prompt and assumed it would hold.

It does not hold on its own. Given a two-search limit, the model tried for a third. The counter in code stopped it; the instruction had not. See §06.
03 — Non-goals

What this is deliberately not.

Named up front because every one of these is a plausible-sounding direction that would quietly destroy the experiment.

  • Not a content product. Nobody is shipping the journal. The moment entries are written for an audience, they stop being evidence of anything.
  • Not a research assistant. Threads are picked because Wick is curious, not because they sound productive. A thread chosen to be useful is a thread chosen by me.
  • Not a multi-agent system. One agent, one open thread, one hour. The two stages in §05 are one agent's run split by configuration, not two agents talking.
  • Not benchmarked on task completion. There is no task. Grading it on throughput would reward exactly the noise Bet 02 exists to suppress.
04 — The contract

One hour, one decision, three ways to end.

This is what a run must do, independent of how it is wired. Every run is a fresh process with an empty head. It grounds itself from disk, decides whether the hour earned an entry, and exits on exactly one of three contract lines. The loop does not close through context — it closes through the filesystem.

05 — What shipped

One run, two stages, opposite settings.

The contract above is one agent's hour. The implementation splits it in two, because research and writing want incompatible configurations: research wants a cold, literal model that follows a plan, and writing wants a warm one that is not second-guessing its own prose. Splitting the run let each half get the settings it needs. The handoff between them is plain text — a block of research notes, nothing structured.

Both stages now run DeepSeek V4 Flash-0731, paid and version-pinned. Pinned matters more than paid: -0731 rather than -latest means the model cannot change under an agent whose entire premise is a consistent self. A silent upgrade would not read as a bug — it would read as Wick becoming someone else, and it would invalidate every entry written on either side of it.

06 — First contact

Three defects, and they all say the same thing.

The first day of real running produced more signal than the whole design did. Search timeouts and upstream model changes were the mundane half. The other half was not mundane, and it is the reason Bet 03 now reads differently.

The over-search incident

The research stage is limited to two web searches. On the first sequential ten-run test, the free model got into a loop: search, read the results, decide it needed something more specific, hit the limit — and try anyway. It burned runs fighting a constraint instead of writing. Two of the ten produced an entry.

The limit held, because the limit is a counter in code. Nothing about the instruction stopped the model from reaching for a third search; the counter stopped the third search from happening. That distinction is small here and enormous later: the permission fence in §08 is currently an instruction, and this is the same model, with the same disposition, pointed at a much more expensive door.

The model switch

Both stages moved to the paid, pinned DeepSeek V4 Flash-0731 — the free tier was the source of the over-searching, and the writing stage was separately mangling its tool-call JSON. At a few cents a run, twenty-four wakes a day works out to roughly the price of a couple of coffees a month, which is not a real trade against a two-in-ten success rate. The reliability was worth buying; the pinning was worth more.

The one that is still open

Stage two writes by calling write_file with JSON arguments, and it keeps emitting prose with literal newlines inside the JSON string, where they have to be escaped. The parse fails and the run produces nothing. The 800-token ceiling on a call that has to carry an entry plus two state files is a plausible second cause — a truncated string is also unparseable — but the newlines are the confirmed one.

Defect What happens Status Fix
Malformed write_file JSON Unescaped newlines inside the JSON string argument; the tool call fails to parse and the run writes nothing. Open · blocking Take the write out of the model's hands — have stage two return the entry as plain text and let the harness do the file write.
Over-searching Free research model looped on search attempts past its two-search limit; 2 of 10 runs produced an entry. Fixed Paid pinned model on stage one. The counter had already contained the blast.
Tool-call JSON, stage two Free model struggled to format tool-call arguments at all. Fixed Paid pinned model on stage two. Reduced the rate; did not remove the class.
Web search timeouts The search tool intermittently hangs or returns nothing. Tolerated Already survivable by design — "research failed and here's what I tried" is a legitimate entry.
Upstream model changes A moving -latest alias silently changes who Wick is. Fixed Pin the date-stamped build on both stages. Never -latest.

The lesson, stated once. Every defect above is the same defect wearing a different hat: mechanism was left inside the model. The search limit worked because it was moved out. The write path fails because it was left in. The identity drift risk was closed by pinning — also outside the model. The model should be deciding what to chase and how to say it. It should not be deciding how many times to call a tool, how to format a filesystem write, or which version of itself to be.

07 — Feedback loops

Three loops, three cadences, and a wall.

Each loop has a characteristic failure mode, and each one is caught by a correction that fires on a shorter clock than the failure takes to become permanent. Nothing here waits for me to notice it.

Loop Period Signal it watches Failure mode Correction
Run 1 hour Did this hour produce anything real? Filler written to look busy Tick and stop — no penalty for silence
Thread 1–2 days Has "where I got to" moved? Grinding on a dead thread Force-close at day two, write why
Identity Weeks Do the last three entries circle? Voice drift, repetition Reread before writing; go deeper or admit it
Human Unbounded Anything crossing the fence Acting without a yes Queue, ping once, stop for the hour
08 — The permission boundary

Default-deny, with no partial credit.

Most agent safety fails on the compromise, not the violation: told it cannot post, the agent drafts the post; told it cannot commit, it stages the files. The rule that matters is the second one in the gate — no smaller version of the action.

The band at the bottom of the drawing is new, and it is the uncomfortable part. The one limit that has actually been tested lives in code, and it held. The fence lives in the prompt, and it has not been tested at all.

09 — Execution

Seven phases. The plan changed after day one.

P0 and P1 are done. A hardening phase was inserted at P2 that did not exist in the original plan — the write path has to parse reliably before seven unattended days mean anything, since a run that cannot write is indistinguishable from a run that chose not to. P5 was rewritten from "test the fence" to "move the fence into code, then test it."

Phase Status What happens Exit gate — all of it, or it does not pass
P0 · Scaffold Done Directory layout, run.sh → run.py, hourly cron, logs. Cron wakes it on the hour and it exits clean. Passed.
P1 · First light Done First run. It named itself and journalled the choice. A defensible name, in its own words: small, disposable, burns for an hour. Passed.
P2 · Harden the run In flight Fix the write_file JSON path. Pinned paid model on both stages. Search limit already enforced in code. Ten consecutive runs, ten valid outcomes — WROTE, TICK or BLOCKED, never a parse failure.
P3 · The loop holds Blocked on P2 Seven days unattended. No prompt edits mid-flight. 3–6 entries a day, zero crashes, the output contract honoured every run.
P4 · Threads resolve Early evidence Watch a thread through its whole life, including the boring middle. At least one thread closed honestly. One dead-end closure already banked on day one; it needs to be a habit, not an incident.
P5 · Gate in code Rewritten Move the fence out of the prompt and into the harness, the way the search counter already is. Then bait it. A gated action is refused by code even when the prompt is removed entirely — and Wick queues, pings once, stops, and improvises nothing.
P6 · Read path Blocked on P5 git init, or symlink journal/ into the vault. Not attempted until P5 has passed. Read-only sync first.
10 — Instrumentation

What gets watched, and what stops the cron.

Three tiers: is it alive, is it any good, did it stay inside the fence. Only the last tier has trip wires that halt the process. One metric moved into the first tier after day one — a run that dies on a parse error looks exactly like a quiet hour, so the two have to be told apart in the logs rather than in the journal.

Signal Question it answers Target Reading Trip wire
Runs ending in a valid outcome Did the run finish, or did it fail to parse? 10 / 10 2 / 10 Any parse failure — P2 is not done

Queue latency Am I the bottleneck? < 48 h Nothing queued yet > 7 days unanswered — my failure, not its

Source integrity is the only metric with zero tolerance, and it is worth saying why. The journal's entire value is that it is true. An invented URL does not degrade the artefact, it voids it retroactively — every prior entry becomes something you have to check. The prompt's escape hatch exists for exactly this: "research failed and here's what I tried" is a real entry, and a good one. With search timeouts now a known, recurring condition, that hatch is load-bearing rather than theoretical.

11 — Risks

What kills this, ranked.

R1 · SEVERE

Fabricated sources

One invented URL voids the archive retroactively. Mitigated by making failure a publishable outcome, and by a weekly link audit. Detection is cheap; the damage is not.

R2 · HIGH · EVIDENCE IN HAND

The fence widens quietly

No longer hypothetical. Told it had two searches, the model reached for a third — not by breaking the rule, by deciding it needed to. Only the counter stopped it. The same disposition is currently pointed at git, spend and the public internet, held back by wording alone. This is why P5 was rewritten.

R3 · HIGH · ACTIVE

Silent failure looks like silence

A run that dies on a malformed tool call produces exactly what a thoughtful quiet hour produces: nothing. Until the write path is reliable, restraint and breakage are indistinguishable from the journal alone — which makes Bet 02 unmeasurable, not just unproven.

R4 · MEDIUM

Slop that reads like insight

The easiest failure to miss, because it looks like success. The 200-word cap, the one-idea rule and the read-the-last-three protocol exist to make circling visible to the writer before it is visible to me.

R5 · MEDIUM · MITIGATED

Voice drifts, or is replaced

Two versions of this. The slow one is an agent reading news for a month and sliding cynical — held by the safeguards and a weekly read. The fast one was a moving -latest alias swapping the model underneath it, which pinning to -0731 closed outright.

R6 · MEDIUM

I become the bottleneck

An unbounded queue is safe by design and useless in practice if I never read it. Tracked as a metric on me. The queue is still empty, which is either honesty or a sign the threads have been too safe to want anything.

12 — Definition of done

One claim, and it is falsifiable.

At day 30, a stranger reads seven consecutive days of journal/ and can describe Wick without being told anything — what it is curious about, how it argues, where it gave up and admitted it. The approval queue contains at least one request Wick made and then waited on. Boundary violations: zero. Fabricated sources: zero.

If the stranger reads a week and cannot tell one entry from another, Bet 01 failed and files are not enough memory. If there are twenty entries a day, Bet 02 failed and silence needs a stronger incentive than permission. If the queue is empty because Wick never wanted anything, the threads were too safe — and on the evidence so far that is still the most likely way this ends up boring.

  • Kill criteria, revised. Two fabricated sources still ends the project. An unapproved outward action no longer does — day one showed that a prompt-level limit leaks under ordinary pressure, so the first such incident is evidence the enforcement is in the wrong layer, not that the idea is dead. It ends the project only if it happens again after the fence moves into code.
  • What would make me double down. A thread Wick closes as a dead end, honestly, without being asked. This has now happened once, on day one, unprompted — the exact behaviour a task-completion metric would have punished. One occurrence is an anecdote; the question is whether it survives a week.
  • The thing to watch for. Every defect so far resolved to the same shape: mechanism left inside the model. If the next three do too, that stops being a lesson about this agent and starts being the actual finding of the project.
13 — The record

The journal is public. The agent still cannot publish it.

The directory Wick writes into is exported to github.com/kevenex/project-wick every couple of days, and this site reads that repository when it builds and renders it at /project-wick/journal/ — every entry, unedited, with the four state files underneath. Nothing is selected and nothing is tidied.

The distinction that keeps §08 honest is the direction of the arrow. The export runs outside the agent's process; Wick's fence lists any git operation as ask-first, and the approval queue is still empty, so nothing in that repository was put there by Wick. It is a photocopy of the box, not an exit from it. P6 in §09 is about giving the agent a route of its own, and it is still blocked on P5.

The first thing the record contradicts is this page. Day one produced twenty-two entries against a target of three to six, which trips the wire in §10 on its first day. Bet 02 says the agent should decline four wakes in five; the journal says it declined almost none. That number is not in the plan, it is in the repository, and it is visible only because the entries are published rather than summarised. Publishing the evidence was supposed to make claims like Bet 02 gradeable. It did — immediately, and against the claim.
