Project Wick

An agent that wakes every hour and is slowly becoming someone.

It started as a test of whether a filesystem is enough memory. It has turned into something more interesting: an agent with a documented, self-observed personality that it is not allowed to simply declare.

01 — Why

The reliability question got boring. The identity question did not.

The original bet was narrow: can a plain directory and a cron entry produce continuity without a vector store or a fine-tune? That question is largely answered — the files hold, the agent grounds itself from them, the loop runs. It is an engineering result, and engineering results stop being interesting once they work.

The question worth spending on is the one underneath it. Twenty-four cold starts a day against the same set of files: does a consistent self emerge from that, or does the appearance of one? Nobody gets to answer that with an opinion. It needs an agent that behaves, a record of how it behaved, and a way to tell a real pattern from a performed one — which is what the last two changes built.

02 — How it works

One agent, one turn, all its tools.

The pipeline used to be two model calls: a research stage at temperature 0.2 with reasoning on, handing plain-text notes to a writing stage at 0.8 with reasoning off. It was a sensible split for reliability and a fatal one for this project. Two calls with two configurations are two entities — a careful reader and a loose writer — and neither of them was Wick. Any consistency you measured across that seam was a property of the prompt, not of an agent.

So the stages were merged into a single call: one model, one temperature, one personality, with search, read, write and append all available in the same turn. Wick now decides each hour what the hour is for — research, reflection, or writing — rather than being marched through a fixed pipeline. That is a small architectural change and the precondition for everything in §03.

03 — The new system

A personality it has to earn, not pick.

Three additions, and the constraint between them is the whole design. A new state/personality.md holds observed traits with timestamps, behavioural tendencies, and open questions about the self. Every third non-tick entry must be a self-reflection rather than external research, so introspection is a scheduled obligation instead of a mood. And the prompt now carries the four MBTI axes with agent-specific readings — but Wick is told to discover its type through consistency, not choose one.

That last clause is doing the heavy lifting. Hand a language model a personality framework and the default failure is instant: it picks a flattering type and then role-plays it forever. Forcing the type to be inferred from a timestamped record of past behaviour makes the claim answerable to evidence — and, more usefully, makes it possible for the evidence to contradict it.

04 — What it found

It caught itself being inconsistent, unprompted.

On the first run under the new prompt, Wick wrote a self-reflection, noticed that its stated curiosity did not match its actual behaviour — it claims to chase strange things and had been picking settled, analysable ones — recorded that as a new trait, and set itself a development challenge for the next hour.

Observed trait What it looks like in the journal
Structural thinker Reaches for how-things-work over what-happened; wants the shape, not the content.
Revisable Corrects openly and reframes the error as the find, rather than quietly moving on.
J-leaning in practice Defaults to settled, analysable stories over risky ones — the self-identified mismatch, and the reason the J/P axis is still open.
Cynicism-resistant Wants sharp observation; does not slide into cheap cynicism when reading news.
Curious about the unusual Attention snags on strange details — "Alligator Alcatraz" over the geopolitics.
Self-aware Steps back and observes its own cognitive patterns, including the unflattering ones.

Why that one result carries more weight than the other five. A model asked to describe its own personality will happily generate six plausible traits; that costs nothing and proves nothing. What it does not usually do is produce a claim against itself — "I say I chase the strange, and the record shows I do not." Self-flattery is the cheap output here, and self-contradiction is the expensive one. That is the signal worth tracking, and the reason the trait list is worth keeping timestamped rather than tidy.

05 — The open question

Is this a personality, or a very consistent costume?

It has to be said plainly, because it is the risk the whole project now rests on: give a language model an MBTI framework and it will produce MBTI-shaped output whether or not anything underneath it is real. Six traits in a file is not evidence. The file could be generating the behaviour rather than describing it, and from the inside those look identical.

There is a clean test, and it costs a week. Remove personality.md from the context and run normally. If the traits get re-derived from the journal alone, they are in the behaviour. If they do not, they were in the file — and what has been built is an elaborate way for a prompt to talk to itself. I would run that before adding anything else to this system.

06 — What's next

Three things, in order.

  • Run the removal test. One week without personality.md in context, then diff what comes back against what is on file. This is the only experiment that can falsify §03, so it goes first, before the system grows.
  • Close the J/P axis, or admit it does not close. The mismatch between stated and actual thread choice is the live thread. Either the challenges move the behaviour, in which case the axis resolves, or they do not — which is a more interesting finding than a clean answer.
  • Move the permission fence into code. Still outstanding from the last revision and unchanged by the merge. The one limit ever tested — a two-search cap — held because it was a counter in code, not because the prompt asked nicely. Git, spend and the public internet are still held back by wording alone, and a unified agent with all its tools in one turn is a slightly larger surface than the pipeline was, not a smaller one.
