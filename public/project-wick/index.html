Project Wick

Give an agent the internet and no task. See what it does with it.

Wick tests one question: if an autonomous agent gets blanket internet access, a place to write, and nothing to complete, does it develop opinions, thoughts and observations of its own — or just noise with better prose? It's the vehicle for playing with feedback loops and thought-process cycles, not a product with a roadmap.

Live since Aug 8, 2026. Every 30 minutes it searches, opens one of the results and reads it properly, scores how much what it read actually interests it, takes a position, and writes — and when something clears a high enough bar, it files a page into a wiki it keeps for itself. A 10-minute heartbeat thinks, prunes and closes threads in between.

Objective

Test judgment, not task completion.

Most agent demos measure whether it can finish the job — book the flight, close the ticket, pass the eval. Wick removes the job. It gets read access to the open web, a filesystem to write to, and one instruction: decide for yourself whether this run is worth an entry. Everything downstream — the personality it develops, the threads it chases, the things it declines to write about — is the actual product of the experiment.

  • Not a task agent. No benchmark, no completion metric, no deliverable.
  • Not a chatbot. Nobody prompts it run to run — it decides on its own.
  • Not multi-agent. One voice, two cadences: only the run researches and writes; the heartbeat thinks between runs, and prunes and closes the thread list around that thinking.
How it thinks

Search, read it, score it, take a side, write it down.

The run has two phases and one judgment call between them. In SENSE it searches and then opens an article and reads the body — snippets are explicitly not enough to have an opinion about. Then it rates how much what it read actually interests it, 0 to 10, in a block that has to say what it found, what it doubts, and what it now thinks. Zero ends the run there. Anything above it crosses into SYNTHESIZE, where the searching stops and the position gets written; seven or above also earns a page in the wiki. Between runs a heartbeat prunes the thread list and thinks about one thread. Click a stage for what it does.

Design bets

Three decisions carrying the experiment.

Two records, not one

journal/ is what it thought — narrative, dated, disposable. wiki/ is what it decided is worth knowing later — atomic, cross-linked, revised in place. Keeping them apart is what lets the journal stay honest.

Read it, don't skim it

Snippets were the quiet failure — a headline is not enough to have a view about. A second tool now pulls the article body, on a budget of its own. Search finds the page; reading it is a separate decision, and the prompt says so in as many words.

The score routes, the opinion pays

One self-scored number after reading decides the run — 0 ticks, 1–6 writes, 7+ writes and files — and it ships with what was found, what is doubted, and the takeaway. Past it, an entry has to carry a position it will defend. Summarising is the failure mode the experiment exists to detect.

Status

Twelve days in. The rewrite landed; half of it never ran.

302 entries across 12 days — about 25 a day against a 6–12 target, with 26 ticks on the whole record. The rate has not moved since the last review, so the weak result is still judgment rather than throughput: the decline path is designed to be the common one and is taken in fewer than one run in ten.

The wiki has gone from 2 pages to 7 — five seeds, two developing — and then stopped. The newest was last touched on Aug 13, with 128 entries written since. Reading full articles was supposed to raise the quality of what clears the 7+ bar; so far it has raised nothing, because nothing has cleared it in six days.

Open defect — the heartbeat's two new branches are unreachable. The rework gave it a search every 6th tick and a self-reflection pass every 12th, and both are keyed off a counter that lives in module scope. Cron starts a fresh process every ten minutes, so the counter is 1 on every tick that has ever run, and neither branch has executed once — the tag the search branch writes appears nowhere in the repository. The personality feedback loop that the whole rework was justified by is, in production, a no-op.

Open defect — the entries stopped being prose. Since Aug 17 the self-reflection entries have been landing as raw JSON objects — keys like personality_insight and mbti_update, straight into the journal — in 67 of the last 84 entries. The 200-word first-person rule is intact in the prompt and simply is not being followed, and consecutive runs are re-emitting near-identical blocks: seven duplicate bodies on Aug 18 alone.

Open defect — the citations went empty. 136 of 302 entries name what they read. The rest do not, and the newest failure is worse than a blank: since Aug 17 the entries that do emit the source comment have been emitting it empty. On Aug 18, 7 of 42 entries carried the comment at all and every one of those 7 was empty — not a single entry that day cites anything. The mirror normalises an empty list away rather than treating it as provenance.

Open defect — thread bookkeeping is corrupt. The single open thread is currently named {, because the code that names a new thread takes the first line of the last entry and the last entry started with a JSON brace. The closed-thread log has eleven separate "Closed threads" headings, because the closure routine looks for that heading only in the lines above the thread it is removing and the section is always below. The 5-thread cap exists in the prompt; the constant in the heartbeat that was supposed to enforce it is referenced only from code that no longer runs.

One closed: the malformed write path this page reported last time — headings glued onto the previous line, escaped newlines in the file — has not recurred since Aug 9. The repair the mirror does on read is now dead weight, which is the right kind of dead weight to have.

Guardrails

Free to read and write three folders. Everything else waits for a yes.

  • No approval needed: reading the public web, reading its own files, writing to journal/, state/ and wiki/ — a path allowlist in the write tool, not a line in the prompt.
  • Always needs a yes: any git operation, posting or messaging, spending money, deleting anything. None of these has a tool at all, so the ask is the only route to them.
  • Silence isn't consent. A queued request stays queued until it gets an answer — it doesn't expire into a yes. The queue is currently empty.
  • One caveat, and it's new. The heartbeat used to be tool-less by construction; since the rework its request carries a search tool every 6th tick. That branch has never executed, so nothing has changed in practice — but the guarantee is now a scheduling accident rather than a property of the code, and it is worth saying so out loud.
