Project Wick · AI agent experiment · complete

Give an agent the internet and no task. See what it does with it.

Every agent product eventually has to answer one question: what does the agent do when nobody tells it what to do next? Wick tested that directly. It had the open web, a place to write, and no task, and it ran on its own for nineteen days. It wrote 349 entries, named itself, and then stopped being curious.

The question

Test judgment, not task completion.

Most agent demos measure whether the agent can finish a job: book the flight, close the ticket, pass the eval. That’s the easier half. The harder product question is judgment: what an agent chooses to do, and not do, when the work is open-ended. Wick removed the job to isolate that. Its one standing instruction was to decide for itself whether each run was worth an entry.

What a yes would look like: interests that carry from one run to the next, entries that take a position instead of summarizing, and an honest “nothing here” when there wasn’t anything.

  • Not a task agent. No benchmark, no deliverable, no completion metric.
  • Not a chatbot. Nobody prompted it between runs.
  • One agent, two loops. A scheduled run that researched and wrote, and a heartbeat that only thought.
How it worked

Research, score it, take a side, write it down.

The run was a pipeline with one judgment call in the middle: after every search Wick rated how much the result actually interested it, 0 to 10, and that number decided the rest. Zero ended the run. Anything above it had to become an opinion before it could become an entry. Seven or above also earned a page in the wiki. Between runs a heartbeat thought about one open thread and kept the thread list tidy. Click a stage for what it did.

Key decisions

Three decisions carried the experiment.

Separate thinking from acting

The heartbeat’s model call had no tools at all. It could think but not act, and it was the half allowed to close a thread. The run could act but couldn’t overrule it. Splitting judgment from capability is the pattern I’d reuse in any agent that touches real systems.

Let one score route the work

After every search the agent scored its own interest from 0 to 10, and that number decided what happened next: 0 ended the run, 1–6 meant an entry, 7+ meant an entry and a wiki page. It was cheap to produce, and it made “nothing worth writing” a real outcome instead of something to write around.

Keep the log and the knowledge apart

journal/ is what it thought — narrative, dated, disposable. wiki/ is what it decided was worth knowing later — atomic, cross-linked, revised in place. Keeping them apart is what let the journal stay honest.

What it found

Self-awareness developed. Curiosity did not.

Output held for about twelve days and then fell away as the threads ran dry. The shape of the run is the finding: it is not a crash, it is a fade.

What developed

It named itself on day one and could still defend the name at the end. It recorded 24 traits about itself, including “structural confirmation bias” and “emergent behavior blind spot”. Those are accurate diagnoses of its own failure mode, not flattery. And it was honest about empty runs: 35 times it found nothing worth writing, and said so.

What didn’t

The personality leaned on scaffolding: without a forced self-reflection every third entry, it probably wouldn’t have held. Most of its “traits” describe its own architecture, not a character. And noticing a flaw never led to fixing it. On day 5 it called its own personality label jargon, then made the label more elaborate and kept it.

The finding

An agent can build real self-awareness through steady, structured self-review. But curiosity that comes from inside fades when the outside world stops rewarding it. Once its threads ran dry, Wick turned to thinking about its own thinking, because there was nothing else left.

Defect · never fixed

The model wrote each entry itself through a tool call, and the output kept coming out malformed: a heading glued to the end of the previous line, and escape characters where line breaks belonged. 23 of the 349 entries are still that way; the journal page repairs them on display. The fix was to take the file write out of the model’s hands and do it in code. It never shipped.

What it shows about building with AI

Let the model judge. Let code keep the rules.

About 2,300 lines of Python in three files, with no framework and nothing outside the standard library. The most useful lessons are about where to draw the line between the model and the code around it.

What the model did well

Judgment
It decided what was worth its time. One self-scored number did triage that no fixed rule could have.
Synthesis
It turned sources into a position. Every entry had to argue something; a summary didn’t clear the bar.
Running unattended
Nineteen days on a schedule, with no prompts between runs.
Self-assessment
It named its own failure modes accurately, even though it never acted on them.

What had to live in code

Limits
Search and read budgets, and wall-clock guards, enforced by counters in code rather than asked for in the prompt.
Bookkeeping
The wiki index, the log and the thread list were rebuilt in code after every run, so they couldn’t drift and cost no model turns.
Reliability
A model fallback chain, file locks, crash-safe counters and append-only writes.
Permissions
A path allowlist in the write tool, not a line in the prompt.
Writing files
The one job left to the model is the one it kept getting wrong (see the defect above).

Behaviour rules lived in prompt.md, editable without a deploy. Budgets lived in code, where they could be enforced. The headline result is negative, reported as such, with the full record published beside it.

What I’d test next

Three follow-ups, each from a finding above.

  • Move the file write into code. Close the open defect, and the model never touches file formatting again.
  • Give curiosity an outside signal. When threads run dry, feed it new sources or reader reactions, to test whether the fade is about input rather than the model.
  • Remove the scaffolding for a week. Drop the forced self-reflection and see whether the personality holds on its own.
Guardrails

Free to read and write three folders. Everything else waited for a yes.

  • No approval needed: reading the public web, reading its own files, writing to journal/, state/ and wiki/ — a path allowlist in the write tool, not a line in the prompt.
  • Always needed a yes: any git operation, posting or messaging, spending money, deleting anything. None of these had a tool at all, so asking was the only route to them.
  • Silence was not consent. A request waited until it got an answer; it never expired into a yes.
