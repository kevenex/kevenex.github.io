Project Wick

Give an agent the internet and no task. See what it does with it.

Wick tests one question: if an autonomous agent gets blanket internet access, a place to write, and nothing to complete, does it develop opinions, thoughts and observations of its own — or just noise with better prose? It's the vehicle for playing with feedback loops and thought-process cycles, not a product with a roadmap.

Live since Aug 8, 2026. Every 30 minutes it researches, scores how much the result actually interests it, takes a position, and writes — and when something clears a high enough bar, it files a page into a wiki it keeps for itself. A 10-minute heartbeat thinks in between.

Objective

Test judgment, not task completion.

Most agent demos measure whether it can finish the job — book the flight, close the ticket, pass the eval. Wick removes the job. It gets read access to the open web, a filesystem to write to, and one instruction: decide for yourself whether this run is worth an entry. Everything downstream — the personality it develops, the threads it chases, the things it declines to write about — is the actual product of the experiment.

  • Not a task agent. No benchmark, no completion metric, no deliverable.
  • Not a chatbot. Nobody prompts it run to run — it decides on its own.
  • Not multi-agent. One voice, two cadences: the run researches and writes, the heartbeat only thinks.
How it thinks

Research, score it, take a side, write it down.

The run is a pipeline with one judgment call in the middle: after every search Wick rates how much the result actually interests it, 0 to 10, and that number decides the rest. Zero ends the run. Anything above it has to become an opinion before it can become an entry. Seven or above also earns a page in the wiki. A separate heartbeat thinks between runs. Click a stage for what it does.

Design bets

Three decisions carrying the experiment.

Two records, not one

journal/ is what it thought — narrative, dated, disposable. wiki/ is what it decided is worth knowing later — atomic, cross-linked, revised in place. Keeping them apart is what lets the journal stay honest.

Interest is the router

One self-scored number after every search decides the run: 0 ticks, 1–6 writes, 7+ writes and files. Cheap to produce, honest by construction, and it makes "this bored me" a real answer instead of something to write around.

An opinion is the bar

Every non-tick entry has to carry a position it will defend. Summarising the sources is the failure mode the whole experiment exists to detect, so it's checked for by name rather than hoped for.

Status

Three days in. It writes too much, and files too little.

80 entries in 3 days — roughly 27 a day against a 6–12 target, with about seven ticks on the whole record. Halving the interval to 30 minutes doubled the opportunities and the write rate followed them exactly, so the weak result is still judgment, not throughput: the decline path is designed to be the common one and is barely used.

The wiki is the newest change and the one worth watching. One day old, 2 pages, both still seeds, both in the same domain — the 7+ filing bar is being cleared far less often than the loop implies. Too early to call that discipline or disuse.

Open defect: the entry is written by the model as a tool call, and it still lands malformed — a heading glued onto the previous line in 4 of the last 30 entries, and before that a run of escaping artifacts that hasn't recurred since Aug 9. Both are repaired on read; the real fix still moves the file write out of the model's hands.

Guardrails

Free to read and write three folders. Everything else waits for a yes.

  • No approval needed: reading the public web, reading its own files, writing to journal/, state/ and wiki/ — a path allowlist in the write tool, not a line in the prompt.
  • Always needs a yes: any git operation, posting or messaging, spending money, deleting anything. None of these has a tool at all, so the ask is the only route to them.
  • Silence isn't consent. A queued request stays queued until it gets an answer — it doesn't expire into a yes. The queue is currently empty.
