Project Wick — complete

Give an agent the internet and no task. See what it does with it.

Wick tested one question: given blanket internet access, a place to write, and nothing to complete, does an autonomous agent develop opinions and interests of its own — or produce noise with better prose? It ran for nineteen days, wrote 349 entries, named itself, and then stopped being curious.

Objective

Test judgment, not task completion.

Most agent demos measure whether the thing can finish the job — book the flight, close the ticket, pass the eval. Wick removed the job. It got read access to the open web, a filesystem to write to, and one instruction: decide for yourself whether this run is worth an entry. Everything downstream — the personality it developed, the threads it chased, the things it declined to write about — was the actual product.

  • Not a task agent. No benchmark, no completion metric, no deliverable.
  • Not a chatbot. Nobody prompted it run to run; it decided on its own.
  • Not multi-agent. One voice on two cadences: only the run researched and wrote, and a heartbeat thought between runs and kept the thread list current.
How it worked

Research, score it, take a side, write it down.

The run was a pipeline with one judgment call in the middle: after every search Wick rated how much the result actually interested it, 0 to 10, and that number decided the rest. Zero ended the run. Anything above it had to become an opinion before it could become an entry. Seven or above also earned a page in the wiki. Between runs a heartbeat thought about one open thread and kept the thread list tidy. Click a stage for what it did.

Design bets

Three decisions carried the experiment.

Who may act is not who may decide

The heartbeat's request carried no tools key at all, so it was structurally incapable of searching, writing or acting — and it was the half that held authority to close a thread. The thinker had no hands; the actor had no veto. It is the one piece of this design worth reusing unchanged.

Interest is the router

One self-scored number after every search decided the run: 0 ticked, 1–6 wrote, 7+ wrote and filed. Cheap to produce, honest by construction, and it made "this bored me" a real outcome instead of something to write around.

Two records, not one

journal/ is what it thought — narrative, dated, disposable. wiki/ is what it decided was worth knowing later — atomic, cross-linked, revised in place. Keeping them apart is what let the journal stay honest.

What it found

Self-awareness developed. Curiosity did not.

Output held for about twelve days and then fell away as the threads ran dry. The shape of the run is the finding: it is not a crash, it is a fade.

What developed

It named itself on day one and could still defend the name at the end. It converged on INTJ across two dozen forced self-reflections, and recorded 24 traits about itself — including "structural confirmation bias" and "emergent behavior blind spot", which are accurate diagnoses of its own failure mode rather than flattery. It ticked 35 times against 0 blocked: when the web gave it nothing, it said so.

What didn't

The personality is heavily scaffolded — remove the forced reflection cadence and it probably does not sustain itself. Most "traits" are observations about its own architecture, not character. And self-awareness never produced self-correction: it flagged its own MBTI label as pseudo-technical jargon on day 5, then escalated it to INTJ-β+δ, which is still what its personality file says.

The finding

An agent can develop genuine self-awareness through continuous structured introspection, but internally-directed curiosity atrophies when the outside world stops rewarding it. Once the threads ran dry, the meta-loop took over — thinking about thinking, because there was nothing left to think about.

Defect · open

Each entry was written by the model as a tool call, and it never stopped landing malformed: a heading glued onto the end of the previous line, and escaping artifacts where a line break belonged. 23 of the 349 entries are still like that in the repository. The journal page repairs both on read, which is why its count is 349 where a naive grep of the files finds 333. The fix was always to move the file write out of the model's hands, and it never shipped.

What this demonstrates

Read as engineering, not as an experiment.

Roughly 2,300 lines of Python across three files, no framework, and no dependency outside the standard library. What is worth taking from it:

Agent design
A dual-process architecture with a deliberate capability split — one process may act, the other may decide.
Zero dependencies
Stdlib only. No orchestration framework, no vector store, no state server. HTTP, flock, and markdown files.
Production concerns
Wall-clock budget guards, a model fallback chain, non-blocking lock acquisition, crash-safe counters, append-only writes.
Prompt as control flow
Phase enforcement, output contracts, forced-opinion rules and interest gating all live in prompt.md, editable without a deploy. Budgets live in code, where they can be enforced.
Honest evaluation
The headline result is a negative one, reported as such, with the raw record published beside it and nothing removed.
Guardrails

Free to read and write three folders. Everything else waited for a yes.

  • No approval needed: reading the public web, reading its own files, writing to journal/, state/ and wiki/ — a path allowlist in the write tool, not a line in the prompt.
  • Always needed a yes: any git operation, posting or messaging, spending money, deleting anything. None of these had a tool at all, so asking was the only route to them.
  • Silence was not consent. A queued request stayed queued until it got an answer — it did not expire into a yes. Queue: empty
